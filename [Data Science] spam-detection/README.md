# Email Analysis and Classification for SPAM Detection

End-to-end NLP project: a **spam classifier**, **topic modelling** of the spam emails and **named-entity extraction** of the organisations mentioned in legitimate emails. Everything is in the notebook [`spam_detection.ipynb`](spam_detection.ipynb).

**Tech stack:** Python 3.12, spaCy, scikit-learn, LightGBM, XGBoost, gensim (LDA, Word2Vec), NetworkX.

## Results

### Classifier (hold-out test set)
The test set was used **once**, after every model and hyperparameter choice had been made with 5-fold cross-validation on the training set only.

| Model | Test emails | Accuracy | Precision (spam) | Recall (spam) | F1 (spam) | ROC AUC |
|---|---|---|---|---|---|---|
| LinearSVC + TF-IDF (sigmoid-calibrated) | 932 (292 spam) | 0.988 | 0.973 | 0.990 | 0.981 | 0.997 |

Confusion matrix: 632 ham and 289 spam classified correctly, **8 false positives** (legitimate emails flagged as spam) and **3 false negatives**. The result is consistent with the cross-validation estimate (F1 0.973 ± 0.005); the small difference is within the sampling uncertainty of a test set with only 11 errors (about ±1 point).

### Model comparison (5-fold CV on the training set, 3,728 emails)

| Model | Features | F1 (spam) | Precision | Recall | ROC AUC |
|---|---|---|---|---|---|
| **LinearSVC** | TF-IDF | **0.972 ± 0.004** | 0.971 | 0.974 | 0.997 |
| LightGBM | Word2Vec | 0.959 ± 0.006 | 0.957 | 0.960 | 0.997 |
| XGBoost | Word2Vec | 0.955 ± 0.008 | 0.950 | 0.960 | 0.996 |
| Logistic Regression | TF-IDF | 0.950 ± 0.012 | 0.912 | 0.991 | 0.996 |
| Multinomial Naive Bayes | TF-IDF | 0.948 ± 0.006 | 0.924 | 0.974 | 0.985 |
| LinearSVC | Word2Vec | 0.942 ± 0.008 | 0.928 | 0.957 | 0.991 |
| Logistic Regression | Word2Vec | 0.938 ± 0.010 | 0.913 | 0.965 | 0.991 |
| MLP | Word2Vec | 0.931 ± 0.009 | 0.892 | 0.975 | 0.990 |
| Random Forest (max_depth=7) | TF-IDF | 0.840 ± 0.011 | 0.725 | 1.000 | 0.990 |

- **LinearSVC + TF-IDF is clearly the best** (about 2 standard deviations ahead of the runner-up). The gradient-boosting models overfit (train F1 = 1.000), the Random Forest underfits (it flags almost everything as spam).
- **Hyperparameter tuning did not meaningfully help**: LinearSVC 0.9723 → 0.9732 (C=0.3, no class weights, squared hinge) and LightGBM 0.9586 → 0.9630, both within one standard deviation. The result is robust to the choice of parameters.
- **Calibration costs nothing**: the sigmoid-calibrated LinearSVC (used to expose spam probabilities) has the same CV F1 as the uncalibrated one (0.9732 in both cases).
- **Deduplication**: 511 near-identical emails (474 ham, 37 spam) were removed *before* splitting, so that copies of the same email cannot end up in both train and test. The CV score barely moved (0.975 → 0.972), so duplicates were not inflating the results.

### Topics and organisations
- **Topic modelling (spam only):** LDA with 5 topics (financial fraud, business & investment, pharmaceutical & product promotion, marketing & mailing lists, software & HTML formatting), cross-checked with Word2Vec + KMeans clusters. The cosine distance between topics is small (about 0.08–0.31), i.e. spam topics share much of their vocabulary.
- **NER (legitimate emails):** organisations extracted with spaCy plus manual cleaning rules; the co-occurrence network shows **Enron** as the dominant organisation, a consequence of the corpus the legitimate emails come from.

### Exported pipeline
The notebook exports a single object (`spam_detector.pkl`) that takes a raw email and returns its label, the spam probability and, for spam, a topic tag. The exported model is trained on **all** the (deduplicated) data, while the metrics above come from the model trained on the training set only. The file is generated by the last cells of the notebook and is not tracked in the repository; loading it requires the same class definitions as the notebook.

## Approach
1. **Deduplication** on a normalised text key (lower case, digits masked), then a stratified 80/20 train/test split (3,728 / 932 emails; 31% spam).
2. **Preprocessing** with spaCy (header tags and URLs removed, lemmatisation, stop-words and non-alphabetic tokens dropped), computed once because it is stateless (no leakage); everything that is fitted (TF-IDF, Word2Vec, scaler, classifier) stays inside the cross-validated pipelines.
3. **Model comparison** with 5-fold stratified CV on the training set (9 model/feature combinations), then **grid search** on the two finalists.
4. **Calibration check** (CV) and **final evaluation** on the test set, run once.
5. **Topic modelling and NER** on the spam and non-spam emails respectively.

## Limitations
- All legitimate emails come from a single corporate corpus (Enron): the classifier may learn corpus-specific vocabulary in addition to spam features, and it was **not tested on emails from other sources**.
- The test set is small (11 errors), so the metrics carry an uncertainty of about one point. The two error types are not symmetric (8 false positives vs 3 false negatives).
- Topic labels were assigned manually and not validated quantitatively; the NER output relies on manual cleaning rules and was not checked against a labelled sample.
- The exported pipeline is trained on all available data, so it has no hold-out evaluation of its own.

## How to reproduce
```bash
pip install -r requirements.txt   # includes the spaCy model en_core_web_sm
```
Open `spam_detection.ipynb` and run all cells in order; the dataset is downloaded from the link below. The cross-validation of the 9 models takes a few minutes; the LightGBM grid search is the slowest step (about half an hour on a laptop CPU).

A company specialized in Artificial Intelligence–based automation, aims to develop a software library for analyzing and classifying incoming emails.

## Project Objectives
Based on an email dataset provided by the CTO, the project aims to:

- Train a **classifier** to identify SPAM emails.
- Identify the **main topics** among emails classified as SPAM.
- Compute the **semantic distance between topics** to evaluate the heterogeneity of SPAM content.
- Extract information about **organizations mentioned** in **NON-SPAM** emails.
